User guide

Everything you need for the first afternoon with ygd-editor, in plain words. Ten minutes to read, and you can come back to any section from the list.

The idea in one minute

A git worktree is a second folder for the same repository, checked out on another branch. Instead of switching branches in one folder — and stashing, rebuilding and losing your place every time — you keep one folder per task.

ygd-editor is built around that: the left panel lists your worktrees, the middle shows what changed in the one you picked, and the right runs an AI agent inside it. Two agents on two tasks work in two folders and never collide. When one is waiting for an answer, the header inbox tells you.

Your first ten minutes

On a fresh install the start page shows a Get set up checklist: git, an AI provider, a repository, a first worktree and a first session. Each step has the button that does it and ticks itself when it is done; Hide this checklist puts it away for good. Here are the same steps in more words.

  1. Open a repository. On the start page choose Open repository and pick a folder that already has git in it, or Clone repository with a GitHub, GitLab or any git URL. Recent repositories stay on the start page.
  2. Create a worktree. New worktree (⌘N) suggests a branch name from the task and a folder to put it in; both are yours to rename to whatever convention you use. Git does not allow spaces in a branch name, so they become dashes and the dialog shows you the result before creating anything. Where worktrees go on disk, and an optional suggested prefix, are Settings › Git.
  3. Start a session. + Session in the right panel picks an agent and a model; the default agent is Settings › Default agent. Type what you want in the composer. @ attaches files or context such as the current diff, / runs the agent’s commands, # its skills. ⌘↵ sends.
  4. Let it work — or stop it. The transcript shows every tool the agent uses. When it needs permission for something you have not pre-approved, the session turns to waiting, the header inbox counts it, and you allow or deny — “Always allow” remembers your choice for that worktree. Stop interrupts; prompts you type while it works are queued.
  5. Review the changes. The Changes tab lists every touched file with who changed it. Click a file for the diff; select lines and choose Explain or Ask to change to send them back to the agent. A warning marks files another worktree of the same repository also touches.
  6. Commit, push, open the PR. Tick the files to stage, write the message or Draft with AI, Commit. Push sets the upstream; Open pull request fills title, body (drafted from the diff if you want), draft flag, reviewers and labels, and hands off to gh or glab. The worktree card then shows the PR and its checks.

Day to day

The main worktree — the folder you opened the repository at — is listed with the others and is the one new worktrees branch from. Select it and click its branch name in the header: a search box drops down over every branch — yours, or one that only exists on the remote, which it checks out as a new tracking branch. Type to narrow it, arrow keys and Enter to switch. A branch another worktree already holds is listed but greyed out, because git allows a branch in one worktree at a time.

Update from base on a worktree fetches and rebases it on the base branch; conflicts stop with the files listed, you resolve them, stage and Continue. Fetch refreshes ahead/behind counts. The Terminal tab is a real shell in the worktree folder; Activity is the timeline of what happened there — commits, pushes, sessions — and survives restarts.

Handing off. A session can move to another worktree from its menu, transcript included, when you realise the work belongs on another branch.

Removing a worktree ends its sessions, archives their logs and forgets its permission rules; the branch stays unless you delete it. Settings › Git can delete the worktree by itself after its PR merges.

Multiple repositories. Open as many as you like; the header switches between them, and the inbox counts waiting sessions across all of them.

Git without a terminal

Pull and Update from base are two things. Pull brings in what was pushed to your own branch — a teammate’s commit, say — so your next push goes through; when both sides have new commits it rebases or merges as Settings › Git says, or asks. Update from base, in the ··· menu, is the other job: catching up with the base branch.

Conflicts. When a rebase, merge, revert or cherry-pick stops on conflicts, open the file and resolve it block by block: keep one side, the other, or Keep both — or take a whole file, or Ask the agent. The two sides are named for what is happening, so you never have to guess which one is “ours”. Mark resolved, then Continue on the banner.

Amend. The commit box has an Amend switch. A commit you have not pushed is simply rewritten. One you have pushed is never force-pushed: the app puts it on a new branch, pushes that, opens a new pull request and closes the old one with a link to the new one.

History. Right-click a commit in Activity to Copy SHA, Show changes, Revert it, or Cherry-pick into… another worktree.

Pull requests. The PR card lists every check, each reviewer’s verdict and the review comments with their file and line. Address review hands the open comments to the agent; Merge offers the methods the repository allows and says why when it cannot merge yet. When work has landed, Clean up merged worktrees… removes every finished worktree in one go and names the ones it left alone.

Forks. In a fork, origin is your copy and upstream the project. The app reads the base branch from upstream whenever there is one, so a new worktree starts from upstream/main rather than your fork’s stale copy, while pushes and pull requests still go to your fork; Fetch fetches both. Settings › Git › Base remote picks another remote, and the Remotes dialog tags it base.

Bare repositories. A repository opens whole from any of its folders: the main one, a linked worktree, a bare api.git with its worktrees beside it, or a proj/.bare layout. Every worktree is listed. A bare repository has no main worktree, so any worktree can be removed, new ones go beside the bare folder (api--fix), and Make current and switching the main worktree’s branch are not offered.

Reviewing what an agent did

One turn at a time. Every turn that changes files ends with a line under it in the transcript — Changed 4 files · +120 −8. Click it and the Changes tab shows only what that turn did. Undo this turn… lists what will happen to each file first, then takes the turn’s changes out: a file nobody touched since goes back to how it was, a file you or a later turn edited keeps those edits, and where both changed the same lines you get conflict markers to resolve. The undo is a turn of its own, so it can be undone too.

Hunk by hunk. Each block of a diff has Stage and Discard (Unstage once staged); select some lines to stage or discard just those. A file that is partly staged gets a Staged / Unstaged switch above its diff.

Finding an old conversation. Search sessions, at the top of the sessions panel, looks through what was said in this worktree, the repository or the workspace — and, if you tick archived, in worktrees you have since removed. A result opens the session at that message. Right-click a session for Export transcript…: a Markdown file with the prompts, the answers and the tool calls. Nothing in it is hidden, so read it before you share it.

Reading a long change. The Changes list groups files by folder — the folder button beside the filter switches to a flat list — and the filter keeps the paths that contain every word you type. Tick Viewed (V) on each file you have read: the tick goes away by itself if the agent changes that file again, and Next unviewed (⇧N) takes you to the next one. In the diff, N and P jump from hunk to hunk and W wraps long lines. Changed words are highlighted inside a line, code is coloured by language, side by side turns unified when the panel is narrow, images show before and after, and a Markdown file can be shown Rendered.

Discarded by mistake? Discard, Discard all changes, discarding a hunk or a few lines, and force-removing a worktree all keep what they throw away. The toast’s Undo brings it back; later, Stashes › Recently discarded has Restore, and Save as stash turns an entry into an ordinary stash — the way back to the changes of a worktree you removed. Stash all changes offers an Undo too.

Big repositories. With more than 2,000 untracked files the list shows the first 2,000 and a line per folder counting the rest; Stage all, Commit and .gitignore still cover every one. Untracked files over 10 MB are left out of turn checkpoints, and the turn’s footer says how many. If reading the worktree takes more than 5 seconds the turn gets no checkpoint at all, and its footer says it cannot be opened or undone. Changes inside node_modules, dist, .next and target no longer refresh the list, and edits made outside the app show up even during a long push or fetch.

Agents at work

Reading the transcript. Answers show as formatted text, and every code block has a Copy button. Three or more tool calls in a row fold into one line that opens to show them. A path to a file of the worktree is a link: a changed file opens its diff, any other opens in your editor. Scroll up to read and the transcript stops following; Jump to latest takes you back. If a session was stopped while it was asking for permission, the transcript says so.

Long sessions. A session opens on its latest messages, and Show earlier messages loads the rest when you want it. To keep the history from growing for ever, Settings › Default agent has Keep sessions for (days) and Session storage limit (MB): when the app starts, it deletes what is older or over the limit. Both are off until you set them.

Stopping really stops. Stop, removing a worktree and quitting the app also end whatever the agent started — a dev server, say. Changing the model does not, and neither does the idle limit: Settings › Default agent › End idle agents after (30 minutes unless you change it; empty means never) ends an agent that has been idle that long, to give back its memory, and your next prompt picks the conversation up again. If the app crashed with agents still running, the next launch offers to Stop them or Leave running.

Your shell’s environment. Agents get what your .zshrc or .bashrc exports — a proxy, API keys, AWS_PROFILE — just as if you had started them from a terminal, even when the app itself was opened from the Dock or a menu rather than a terminal. Settings › Editor & terminal › Use my shell environment turns it off, and lists the names of the variables it brings, never their values. Windows does not need it: apps there get your variables already.

Worktrees that are ready to run

A new worktree has none of your ignored files — no .env, no node_modules. Settings › Worktree setup fixes that once: files to copy from the main worktree (.env*, say), commands to run in the new worktree’s terminal (pnpm install), and a port base, so each worktree gets its own port as YGD_PORT and two dev servers stop fighting over the same one. The worktree’s terminal and its agents also get YGD_WORKTREE and YGD_BRANCH. The New worktree dialog shows what setup will do; Run setup again is in the ··· menu.

A repository can carry the same recipe in .ygd/worktree.json. Its commands come from whoever wrote the branch, so the app shows them and asks before running them the first time — and again whenever the file changes.

Terminals

Several terminals. + in the Terminal tab opens another shell beside the worktree’s own; double-click a tab to rename it. Run ▾ in the toolbar starts saved commands — dev: pnpm dev — each in a terminal named after it, with Restart and Stop. @terminal:dev in a prompt attaches what that terminal printed.

They keep running. A terminal keeps its program and its history while Settings, the start page or the compare view is open, so vim, htop or a dev server is exactly as you left it. ⌘F (Ctrl+Shift+F on Windows and Linux), or the magnifier at the end of the tabs, searches the scrollback. ⌘-click (Ctrl+click) opens a link in your browser. ⌘⇧] and ⌘⇧[ (Ctrl+PageDown and Ctrl+PageUp) go to the next and previous terminal. Closing a terminal that is still running something asks first, and names the program.

Try it several ways

Not sure which agent or model will do a task best? Tick Try it N ways in the New worktree dialog and pick two to four attempts — Claude Code, Codex and Gemini CLI, or one model three times. Each gets its own worktree from the same base (login-a, login-b…), setup runs in each, and the same first prompt goes to all of them. Every attempt counts against your budget, and the dialog says so.

The attempts sit together in the sidebar. Click their entry to compare them side by side: status, files and lines changed, cost, turns and time, a quick diff, and your check command — pnpm test, say, from Settings › Worktree setup — run in each on demand. Keep this one removes the others after listing them, can give the winner the plain branch name, and can go straight on to Make current or a pull request.

Working on several repositories: workspaces

A workspace is a named set of folders the app holds open together. A gateway, a web console and a folder of notes are often one piece of work, and a question about one of them is usually answered in another — a workspace is how you tell the app they belong together.

Making one. Open a second repository while one is already open and the app asks where it goes: add it to what you are working in, start a new workspace with both, or open it on its own. Escape means “on its own”. You can also start one from the start page with New workspace, and add or remove folders later from the workspaces button in the header. Removing a folder from a workspace never deletes anything — only the set changes.

From VS Code. If your team already keeps a .code-workspace file, Open workspace file… reads it: the same folders, in the same order, named the way VS Code names them. Comments and trailing commas in the file are fine. Folders that are not git repositories are kept — they just have no worktrees — and a folder that has gone missing is reported rather than quietly dropped. Save to file writes it back, leaving the parts the app does not use untouched, so the same file keeps working in both tools.

What the sidebar shows. Worktrees grouped by repository, each group foldable, with the filter matching a branch or a repository name so you can find a branch without remembering where it lives. A folded group still shows what is running inside it, and still says when a session is waiting. One repository shows no groups at all.

What the agents can see. A session still runs in its worktree — that is where git and every relative path belong — but it can read the workspace’s other folders too, so “where does this call end up?” can be answered from either side. A session that only reads is still only allowed to read, everywhere. There is also a row above the groups, Across the workspace, for sessions that belong to no single worktree: ask those the questions that span the whole stack. They have no branch, no changes and no terminal, because those belong to a worktree.

Settings. Three levels now: Global, the workspace, then a single repository. The default agent, the permission preset and the base branch are usually a property of the stack rather than of each repository in it, so set them once on the workspace; a repository that needs something different still overrides it. The scope selector in Settings picks the level, and a section that is not overriding says where its values are coming from.

The app remembers each workspace separately: come back to one and you land on the repository, worktree and panel layout you left it in.

Testing a worktree in the default one

The place to try a change is the repository's own folder — the default worktree — because that is where node_modules, .env, the build cache and the running dev server already are. The work happens in the other worktrees. Make current brings one of them into the default worktree: its commits, what it has not committed yet and its new files, on top of the default worktree's branch. From then on the header says, on every screen, what the default worktree is running — DEFAULT · feat-a + feat-b · 1 edit — and the sidebar tags the default worktree and the current ones.

Swap puts another worktree in its place. Add stacks another one on top, to try two changes together; where both touch the same lines the load stops on a conflict in the default worktree, and for each file you keep the default side, take the incoming one, or edit it and mark it resolved — then Continue, or Abort back to what was running before.

Fixes made while testing go home. If you — or an agent in the default worktree — fix something while trying a change, Send edits back returns it to the worktree it belongs to, as uncommitted changes there, to review and commit; Undo takes it back until the next step. A file that belongs to several current worktrees, or to none, is asked about rather than guessed. Swap, Add, Refresh and End send the edits back first, so nothing done in the default worktree is lost to them. Send edits back, End and Undo this turn write files the way a checkout would — Git LFS, git-crypt and Windows line endings included; if a filter the repository needs is missing (git-lfs not installed, say), they stop with git’s message instead of leaving pointer files behind.

End gives the default worktree back exactly as it was: its branch, and its own changes, staged and not staged. Every step opens a short preview first — what comes in, what is kept aside, which files would conflict, and anything that stops it right now with the way out. You find them in the ··· menu of a worktree, on a right-click in the sidebar, in the header strip, and on ⌘⇧D / ⌘⇧E.

Settings › Git can refresh a current worktree by itself when its agent keeps working, and run a command after each load — pnpm install when pnpm-lock.yaml changed, say — in the default worktree's terminal, where you see it. Your own git stash is never touched. It needs git 2.40 or newer.

Getting around, and what it cost

⌘K opens the command palette: every action in the app — with its shortcut, or the reason it cannot run right now — plus your worktrees across the workspace, your sessions, the pages of Settings and your recent repositories. Start with > for actions, @ for worktrees, # for sessions; arrows and Enter do the rest.

What it cost. Settings › Budget has a Usage report: a bar per day split by agent, and what each repository and branch spent, over the last 7, 30 or 90 days or any dates you pick, with Export CSV. The figures are the budget’s own, so they always match the spend meter.

Agents and providers

ygd-editor does not talk to any AI service itself. It runs the command-line tools you already have — Claude Code, Codex, Gemini CLI — with your own accounts, so your usage, billing and data terms are exactly the ones you agreed with those providers.

Settings › AI providers connects each provider with your own account: Connect opens the provider’s sign-in page in your browser, and the card then shows the account, the plan and Switch account / Disconnect / Test connection. Codex and Gemini CLI are downloaded by the app the first time you pick them — the card says the version and the size, shows the progress, and Remove download takes it away again; if you have your own copy installed, the app uses that one. Claude Code’s licence does not allow shipping it, so its card offers Install Claude Code, which runs Anthropic’s official installer in the card’s terminal, into your home folder, without an administrator password. The default agent and model, and the permission preset, can differ per repository.

A card also says when the installed CLI is newer or older than the versions this release was checked with. Sessions still run; the note is there so that an incomplete report has an explanation. When Codex loses its connection and retries, the transcript shows a short Reconnecting… note rather than an error.

Permissions

Agents ask before doing things you have not pre-approved. Settings › Permissions has three presets — strict (read only), balanced (read and edit files, ask for anything else) and yolo (also run commands, use the web and push) — plus individual switches for reading, editing, running commands, web access, pushing and deleting. Whatever the preset, an agent can never delete without asking unless you turn that on.

When a request comes in, Approve and Deny answer once; Always allow remembers that tool for that worktree, and the rule goes away with the worktree.

When an agent asks for several things at once, the requests queue on the session card and in the inbox — 1 of 3 — and you answer them in order. Settings › Permissions › Allowed rules lists every “Always allow” by worktree, with the date it was added; Revoke takes effect at once, in a running session too. Auto-deny after (minutes, off by default) refuses a request nobody answers and tells the agent why. Codex and Gemini CLI cannot ask, so their agent bar shows the sandbox mode your switches give them; a click on it opens Settings › Permissions.

Notifications, inbox and budget

Settings › Notifications chooses when the app pings you: when a session is waiting, when one finishes, and when a pull request changes — checks done, approved, changes requested, merged. Pull requests are watched for every worktree in the background, so you hear about them within about five minutes even for one you are not looking at; a merge found that way keeps its offer to remove the worktree until you answer it. Notifications only show while the window is not in front, a click on one jumps to the session, and the dock or taskbar badge can count waiting sessions.

The header inbox has two tabs. Needs input is the sessions waiting on you. Activity is everything the app has told you — finished turns, pull request changes, failures with git’s full output, the toasts you might have missed — and a click on a row takes you to its session or worktree. Unread rows are counted, Mark all read clears them, and the latest 200 are kept across restarts.

The budget bar at the bottom of the left panel is today’s spend across every session. When an agent reports its own cost, that is the figure; otherwise its tokens are priced at the model’s list price, and the rates in Settings › Budget are only for models that have none. The usage popover and a session’s cost tooltip say which it is. Settings › Budget also sets a daily and a per-session limit and a warning threshold; with Pause sessions at the limit on, reaching the daily limit also stops turns that are still running, and a toast says how many.

Settings

Settings (⌘,) are grouped by topic. Appearance sets theme, accent colour, density and fonts; Language switches the interface between English, Spanish, Italian, Polish, French, German and Turkish. Several sections carry a per repo badge: with a repository selected at the top you can override those for that repository only. Dates, times, numbers and costs follow the language you choose, not the system’s.

Everything saves automatically to settings.json in the app’s folder in your home directory; Open settings.json edits the raw file with validation, and the header shows when it was last written. The file names its schema, so an editor such as VS Code completes and checks it when you edit it by hand. Every save keeps the previous file as settings.json.bak; if the file is ever damaged, the app runs on that copy and tells you. An older version of the app never overwrites a file a newer one wrote: it runs on defaults and refuses to save settings until you update again. Workspaces, the inbox and the session lists are kept the same way.

Search settings, at the top, finds any row by what it is called or what it does — type “budget limit” and Budget opens with the cursor in Daily limit; ⌘K finds settings too. A row you have changed shows a dot and its own Reset. Number fields refuse a value the app could not use, say why, and keep the saved one.

Small windows and the keyboard

Small windows. The window goes down to 900 × 680, so the app fits beside an editor on a 13- or 14-inch laptop. Narrower than about 1,180 pixels the sessions panel folds into a rail, and narrower than about 1,000 the worktree list does too. Click a rail to open its panel over the middle; Escape, or a click beside it, puts it away. Your saved layout is left alone: widen the window and the panels are back as they were.

From the keyboard. Each list — worktrees, sessions, terminal tabs, Settings sections, recent repositories — is a single Tab stop. ↑ and ↓ (← and → on terminal tabs), Home and End move along it, Enter or Space picks a row, the Menu key or Shift+F10 opens the row’s menu, and F2 renames a terminal tab.

Questions are the app’s own. Anything that needs a yes — discarding, dropping a stash, merging a pull request — asks in a dialog of the app, in your language, with the action written on the button; Escape means no. Clone, Hand off and Remotes ask before throwing away what you have typed in them.

Updates

Shortly after launch, and every six hours while it stays open, the app checks this site’s releases and tells you when there is a new version. One click downloads it; with Settings › About & updates › Download updates automatically on, it downloads as soon as it is found. Nothing installs until you choose: Restart & update now, Restart later — it then installs when you quit — or Discard.

An update installs only if the release’s signed checksums list it, checked against the certificate built into the app. If they do not, the app says the update is not signed by the project and installs nothing. Settings › About & updates also has Offer updates, which turns the checks off, and Check for updates with the time of the last check.

The first launch after an update says which version you are on, and its What’s new opens the release notes inside the app. Settings › About & updates and the command palette open them too.

When something goes wrong

macOS says it could not verify the app (Move to Trash / Done). Click Done, then System Settings › Privacy & Security › scroll to Security › Open Anyway, and confirm with your password. On macOS 14 or older, right-click › Open does it in one step. If it still refuses, in Terminal: xattr -d com.apple.quarantine /Applications/ygd-editor.app. If it says the app is damaged, the download was corrupted: download it again and compare it against SHA256SUMS.txt.

Avoiding the prompt altogether. Install from Terminal instead: curl -fsSL https://mhguitarte.github.io/ygd-editor/install.sh | bash. It checks the download the way macOS would have and puts the app in Applications; see the download page.

Windows blocks the installer. SmartScreen › More info › Run anyway. The publisher should read ygd-editor release signing.

The AppImage does not start. Run it with --appimage-extract-and-run, or install libfuse2.

A provider shows “Not installed”. Codex and Gemini CLI are downloaded on request: click Download on the card, and if the download fails the card says why (offline, or a file that did not match its checksum and was discarded). For Claude Code, click Install Claude Code on its card; if you installed it yourself, open a terminal, check that claude --version works, then Settings › AI providers › Rescan.

Git errors. The app explains the usual ones in one sentence — credentials, a remote that moved on, a lock file, a dirty tree, conflicts — and keeps the full output in the worktree terminal.

No update appears. Check Settings › About & updates › Offer updates, then Check for updates; the app needs to reach github.com.

An update was refused as not signed by the project. Nothing was installed. Download the installer from All versions and check it as Is my download genuine? explains.

Settings will not save after going back to an older version. The older app leaves files written by the newer one alone, runs on defaults and says which file it is. Update again and everything is where you left it.

Reporting a problem. Settings › Diagnostics shows what a bug report needs: the versions of the app, git and each agent CLI, the PATH agents get, the running agent processes and a live log you can filter. Log levels sets how much is logged — info, git=debug logs git in detail. Prepare bundle… gathers it all in a zip and lists every file for you to read before Save zip…: tokens and API keys are masked, what you typed to agents and terminals is left out, and your home folder shows as ~. Attach it to an issue with what you did, what you expected and what happened.

Uninstalling

Before you remove it — both optional. If a worktree is current in the default one, End it, so the default worktree has its own branch and changes back. To sign out of a provider, use Disconnect on its card in Settings › AI providers: the sign-ins belong to Claude Code, Codex and Gemini CLI rather than to the app, so removing the app does not end them. Then quit ygd-editor.

macOS. Drag ygd-editor from Applications to the Trash — from ~/Applications if the Terminal install put it there.

Windows. Settings › Apps › Installed apps › ygd-editor › Uninstall, or Control Panel › Programs and Features.

Linux. Delete the AppImage file. For the Debian / Ubuntu package: sudo apt remove ygd-editor.

What stays behind. Your settings, workspaces, session history and the Codex and Gemini CLI downloads live in the .ygd-editor folder in your home directory, and uninstalling keeps them, so a reinstall picks up where you left off. To remove them too, with the app’s caches, run this after uninstalling:

macOS:

rm -rf ~/.ygd-editor ~/Library/Application\ Support/ygd-editor ~/Library/Caches/ygd-editor-updater ~/Library/Caches/com.mhguitarte.ygd-editor* ~/Library/HTTPStorages/com.mhguitarte.ygd-editor ~/Library/Preferences/com.mhguitarte.ygd-editor.plist

Windows (PowerShell):

Remove-Item -Recurse -Force -ErrorAction SilentlyContinue "$env:USERPROFILE\.ygd-editor", "$env:APPDATA\ygd-editor", "$env:LOCALAPPDATA\ygd-editor-updater"

Linux:

rm -rf ~/.ygd-editor ~/.config/ygd-editor ~/.cache/ygd-editor-updater

What is never touched. Your repositories and the worktrees you created are ordinary git folders and stay where they are; git worktree remove <folder> removes one. If the app installed Claude Code for you, it stays in your home folder — Anthropic’s documentation explains how to remove it.

Privacy and security

Everything runs on your computer. The app itself connects to the internet for two things: checking this site’s releases for updates, and once a day fetching the public list of models and their prices from models.dev. Agents talk to their providers with your accounts; git talks to your remotes with your credentials. Provider tokens the app keeps are stored in the operating system’s keychain. The interface runs sandboxed, every request that names a path is checked against the repositories you actually opened, and no command is ever built from a shell string. The diagnostics bundle is saved where you choose and sent nowhere.

To check that a download is really ours, see Is my download genuine? on the download page.
