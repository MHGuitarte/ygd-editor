Guide d’utilisation

Tout ce qu’il vous faut pour le premier après-midi avec ygd-editor, en termes simples. Dix minutes de lecture, et vous pouvez revenir à n’importe quelle section depuis la liste.

L’idée en une minute

Un worktree git est un second dossier du même dépôt, sur une autre branche. Au lieu de changer de branche dans un seul dossier — en mettant de côté, en recompilant et en perdant le fil à chaque fois — vous gardez un dossier par tâche.

ygd-editor est construit autour de cela : le panneau de gauche liste vos worktrees, celui du centre montre ce qui a changé dans celui que vous avez choisi, et celui de droite y exécute un agent IA. Deux agents sur deux tâches travaillent dans deux dossiers et ne se heurtent jamais. Quand l’un attend une réponse, la boîte de réception de l’en-tête vous le signale.

Vos dix premières minutes

  1. Ouvrez un dépôt. Sur la page d’accueil, choisissez Ouvrir un dépôt et sélectionnez un dossier qui contient déjà git, ou Cloner un dépôt avec une URL GitHub, GitLab ou n’importe quelle URL git. Les dépôts récents restent sur la page d’accueil.
  2. Créez un worktree. Nouveau worktree (⌘N) propose un nom de branche tiré de la tâche et un dossier où la placer ; vous pouvez renommer les deux selon la convention que vous utilisez. Git n’accepte pas les espaces dans un nom de branche, ils deviennent donc des tirets et la boîte de dialogue vous montre le résultat avant de créer quoi que ce soit. L’emplacement des worktrees sur le disque, et un préfixe suggéré facultatif, se trouvent dans Réglages › Git.
  3. Lancez une session. + Session dans le panneau de droite choisit un agent et un modèle ; l’agent par défaut est dans Réglages › Agent par défaut. Tapez ce que vous voulez dans le compositeur. @ joint des fichiers ou du contexte comme le diff actuel, / exécute les commandes de l’agent, # ses skills. ⌘↵ envoie.
  4. Laissez-le travailler, ou arrêtez-le. La transcription montre chaque outil que l’agent utilise. Quand il a besoin d’une permission pour quelque chose que vous n’avez pas pré-approuvé, la session passe en attente, la boîte de réception de l’en-tête la compte, et vous autorisez ou refusez ; « Toujours autoriser » mémorise votre choix pour ce worktree. Arrêter interrompt ; ce que vous tapez pendant qu’il travaille est mis en file d’attente.
  5. Relisez les modifications. L’onglet Modifications liste chaque fichier touché et qui l’a modifié. Cliquez sur un fichier pour le diff ; sélectionnez des lignes et choisissez Expliquer ou Demander une modification pour les renvoyer à l’agent. Un avertissement marque les fichiers qu’un autre worktree du même dépôt touche aussi.
  6. Commit, push, ouvrez la PR. Cochez les fichiers à indexer, écrivez le message ou Rédiger avec l’IA, Commit. Push configure l’upstream ; Ouvrir une pull request remplit le titre, le corps (rédigé à partir du diff si vous le souhaitez), l’état de brouillon, les relecteurs et les étiquettes, et passe la main à gh ou glab. La carte du worktree affiche ensuite la PR et ses checks.

Au quotidien

Le worktree principal — le dossier avec lequel vous avez ouvert le dépôt — figure avec les autres et c’est de lui que partent les nouveaux worktrees. Sélectionnez-le et cliquez sur le nom de sa branche dans l’en-tête : un champ de recherche se déplie sur toutes les branches — les vôtres, ou une qui n’existe que sur le dépôt distant, qu’il extrait comme nouvelle branche de suivi. Tapez pour filtrer, flèches et Entrée pour changer. Une branche déjà tenue par un autre worktree est listée mais grisée, parce que git n’autorise une branche que dans un seul worktree à la fois.

Mettre à jour depuis la base sur un worktree fait un fetch et un rebase sur la branche de base ; les conflits s’arrêtent avec la liste des fichiers, vous les résolvez, vous indexez et Continuer. Fetch rafraîchit les compteurs d’avance/retard. L’onglet Terminal est un vrai shell dans le dossier du worktree ; Activité est la chronologie de ce qui s’y est passé — commits, pushes, sessions — et survit aux redémarrages.

Transférer une session. Une session peut être transférée vers un autre worktree depuis son menu, transcription comprise, quand vous réalisez que le travail appartient à une autre branche.

Supprimer un worktree termine ses sessions, archive leurs journaux et oublie ses règles de permissions ; la branche reste sauf si vous la supprimez. Réglages › Git peut supprimer le worktree tout seul une fois sa PR fusionnée.

Plusieurs dépôts. Ouvrez-en autant que vous voulez ; l’en-tête passe de l’un à l’autre, et la boîte de réception compte les sessions en attente de tous.

Travailler sur plusieurs dépôts : les espaces de travail

Un espace de travail est un ensemble nommé de dossiers que l’application garde ouverts ensemble. Une passerelle, une console web et un dossier de notes forment souvent un seul travail, et une question sur l’un trouve généralement sa réponse dans un autre : un espace de travail est la façon de dire à l’application qu’ils vont ensemble.

En créer un. Ouvrez un second dépôt alors qu’un autre est déjà ouvert et l’application vous demande où il va : l’ajouter à ce sur quoi vous travaillez, démarrer un nouvel espace de travail avec les deux, ou l’ouvrir tout seul. Échap signifie « tout seul ». Vous pouvez aussi en démarrer un depuis la page d’accueil avec Nouvel espace de travail, et ajouter ou retirer des dossiers plus tard depuis le bouton des espaces de travail dans l’en-tête. Retirer un dossier d’un espace de travail ne supprime jamais rien : seul l’ensemble change.Depuis VS Code. Si votre équipe tient déjà un fichier .code-workspace, Ouvrir un fichier d’espace de travail… le lit : les mêmes dossiers, dans le même ordre, nommés comme VS Code les nomme. Les commentaires et les virgules finales dans le fichier ne posent aucun problème. Les dossiers qui ne sont pas des dépôts git sont conservés — ils n’ont simplement pas de worktrees — et un dossier qui a disparu est signalé plutôt que discrètement écarté. Enregistrer dans le fichier le réécrit en laissant intactes les parties que l’application n’utilise pas, de sorte que le même fichier continue de fonctionner dans les deux outils.Ce que montre la barre latérale. Les worktrees regroupés par dépôt, chaque groupe repliable, avec le filtre qui cherche dans le nom de branche comme dans le nom du dépôt, pour que vous trouviez une branche sans vous souvenir d’où elle vit. Un groupe replié montre toujours ce qui tourne à l’intérieur, et signale toujours quand une session attend. Avec un seul dépôt, il n’y a aucun groupe.Ce que voient les agents. Une session s’exécute toujours dans son worktree — c’est là que vivent git et tous les chemins relatifs — mais elle peut aussi lire les autres dossiers de l’espace de travail, si bien que « où aboutit cet appel ? » peut trouver sa réponse de chaque côté. Une session qui ne fait que lire n’a toujours que le droit de lire, partout. Il y a aussi une ligne au-dessus des groupes, Sur tout l’espace de travail, pour les sessions qui n’appartiennent à aucun worktree en particulier : posez-leur les questions qui couvrent toute la pile. Elles n’ont ni branche, ni modifications, ni terminal, parce que cela appartient à un worktree.Réglages. Trois niveaux désormais : Global, l’espace de travail, puis un dépôt en particulier. L’agent par défaut, le préréglage de permissions et la branche de base sont généralement une propriété de la pile plutôt que de chaque dépôt qui la compose, alors définissez-les une fois sur l’espace de travail ; un dépôt qui a besoin d’autre chose peut toujours les remplacer. Le sélecteur de portée dans Réglages choisit le niveau, et une section qui ne remplace rien indique d’où viennent ses valeurs.

L’application mémorise chaque espace de travail séparément : revenez sur l’un d’eux et vous retrouvez le dépôt, le worktree et la disposition des panneaux que vous aviez laissés.

Tester un worktree dans celui par défaut

L'endroit pour essayer une modification est le dossier du dépôt lui-même — le worktree par défaut — parce que c'est là que se trouvent déjà node_modules, .env, le cache de build et le serveur de développement. Le travail se fait dans les autres worktrees. Rendre courant amène l'un d'eux dans le worktree par défaut : ses commits, ce qu'il n'a pas encore committé et ses nouveaux fichiers, par-dessus la branche du worktree par défaut. Dès lors, l'en-tête dit sur chaque écran ce qu'exécute le worktree par défaut — DÉFAUT · feat-a + feat-b · 1 modification — et la barre latérale marque le worktree par défaut et les courants.

Échanger met un autre worktree à sa place. Ajouter en empile un autre par-dessus, pour essayer deux modifications ensemble ; là où les deux touchent les mêmes lignes, le chargement s'arrête sur un conflit dans le worktree par défaut, et pour chaque fichier vous gardez le côté par défaut, prenez celui qui arrive ou le modifiez et le marquez résolu — puis Continuer, ou Annuler pour revenir à ce qui tournait avant.Les corrections faites pendant les tests rentrent à la maison. Si vous — ou un agent dans le worktree par défaut — corrigez quelque chose en essayant, Renvoyer les modifications le rend au worktree auquel il appartient, en modifications non committées à relire et committer là-bas ; Annuler le reprend jusqu'à l'étape suivante. Un fichier qui appartient à plusieurs worktrees courants, ou à aucun, est demandé plutôt que deviné. Échanger, Ajouter, Rafraîchir et Terminer renvoient d'abord les modifications, donc rien de ce qui a été fait dans le worktree par défaut ne se perd.Terminer rend le worktree par défaut exactement comme il était : sa branche et ses propres modifications, indexées ou non. Chaque étape ouvre d'abord un bref aperçu : ce qui entre, ce qui est mis de côté, quels fichiers seraient en conflit et ce qui l'empêche maintenant, avec la porte de sortie. On les trouve dans le menu ··· d'un worktree, au clic droit dans la barre latérale, dans la bande de l'en-tête et avec ⌘⇧D / ⌘⇧E.

Réglages › Git peut rafraîchir tout seul un worktree courant quand son agent continue de travailler, et lancer une commande après chaque chargement — pnpm install quand pnpm-lock.yaml a changé, par exemple — dans le terminal du worktree par défaut, où vous la voyez. Votre git stash n'est jamais touché. Il faut git 2.40 ou plus récent.

Agents et fournisseurs

ygd-editor ne parle lui-même à aucun service d’IA. Il exécute les outils en ligne de commande que vous avez déjà — Claude Code, Codex, Gemini CLI — avec vos propres comptes, si bien que votre utilisation, votre facturation et vos conditions de traitement des données sont exactement celles que vous avez acceptées auprès de ces fournisseurs.

Réglages › Fournisseurs d’IA connecte chaque fournisseur avec votre propre compte : Connecter ouvre la page de connexion du fournisseur dans votre navigateur, et la carte affiche ensuite le compte, le forfait et Changer de compte / Déconnecter / Tester la connexion. Codex et Gemini CLI sont téléchargés par l’application la première fois que vous les choisissez — la carte indique la version et la taille, montre la progression, et Supprimer le téléchargement le retire ; si vous avez votre propre copie installée, l’application utilise celle-là. La licence de Claude Code ne permet pas de l’inclure, sa carte propose donc Installer Claude Code, qui exécute l’installateur officiel d’Anthropic dans le terminal de la carte, dans votre dossier personnel, sans mot de passe administrateur. L’agent et le modèle par défaut, ainsi que le préréglage de permissions, peuvent varier selon le dépôt.

Permissions

Les agents demandent avant de faire ce que vous n’avez pas pré-approuvé. Réglages › Permissions propose trois préréglages — strict (lecture seule), équilibré (lire et modifier les fichiers, demander pour tout le reste) et yolo (aussi exécuter des commandes, utiliser le web et faire des push) — plus des interrupteurs individuels pour la lecture, la modification, l’exécution de commandes, l’accès web, le push et la suppression. Quel que soit le préréglage, un agent ne peut jamais supprimer sans demander, sauf si vous l’activez.

Quand une demande arrive, Approuver et Refuser répondent une fois ; Toujours autoriser mémorise cet outil pour ce worktree, et la règle disparaît avec le worktree.

Notifications, boîte de réception et budget

Réglages › Notifications choisit quand l’application vous prévient : quand une session attend, quand une session se termine, quand les checks d’une pull request changent. Les notifications ne s’affichent que lorsque la fenêtre n’est pas au premier plan, un clic sur l’une d’elles ouvre la session, et le badge du Dock ou de la barre des tâches peut compter les sessions en attente.

La barre de budget en bas du panneau de gauche est la dépense réelle du jour sur toutes les sessions, tirée des rapports d’utilisation des agents eux-mêmes. Réglages › Budget fixe une limite quotidienne et une limite par session, un seuil d’avertissement, et si les sessions se mettent en pause quand la limite est atteinte.

Réglages

Les Réglages (⌘,) sont regroupés par thème. Apparence définit le thème, la couleur d’accent, la densité et les polices ; Langue bascule l’interface entre anglais, espagnol, italien, polonais, français, allemand et turc. Plusieurs sections portent le badge par dépôt : avec un dépôt sélectionné en haut, vous pouvez les remplacer pour ce dépôt uniquement.

Tout s’enregistre automatiquement dans settings.json, dans le dossier de l’application au sein de votre répertoire personnel ; Ouvrir settings.json modifie le fichier brut avec validation, et l’en-tête indique quand il a été écrit pour la dernière fois.

Mises à jour

Peu après le lancement, l’application consulte les versions de ce site, télécharge la nouvelle en arrière-plan et propose Redémarrer pour mettre à jour. Réglages › Notifications a l’interrupteur Proposer les mises à jour, un bouton Rechercher des mises à jour avec l’heure de la dernière vérification, et Installer les mises à jour automatiquement : activé, une mise à jour téléchargée redémarre l’application toute seule après un décompte de 15 secondes que vous pouvez annuler — seulement quand aucune session n’est en cours ou en attente ; sinon, elle s’installe quand vous quittez. Le premier lancement après une mise à jour indique quelle version vous utilisez et renvoie vers ce qui a changé.

Quand quelque chose ne va pas

macOS dit qu’il n’a pas pu vérifier l’application (Placer dans la corbeille / Terminé). Cliquez sur Terminé, puis Réglages Système › Confidentialité et sécurité › descendez jusqu’à Sécurité › Ouvrir quand même, et confirmez avec votre mot de passe. Sous macOS 14 ou antérieur, clic droit › Ouvrir le fait en une étape. S’il refuse toujours, dans le Terminal : xattr -d com.apple.quarantine /Applications/ygd-editor.app. S’il dit que l’application est endommagée, le téléchargement a été corrompu : téléchargez-la de nouveau et comparez-la à SHA256SUMS.txt.

Windows bloque l’installateur. SmartScreen › Informations complémentaires › Exécuter quand même. L’éditeur doit indiquer ygd-editor release signing.

L’AppImage ne démarre pas. Lancez-le avec --appimage-extract-and-run, ou installez libfuse2.

Un fournisseur affiche « Non installé ». Codex et Gemini CLI sont téléchargés à la demande : cliquez sur Télécharger sur la carte ; si le téléchargement échoue, la carte dit pourquoi (hors ligne, ou un fichier qui ne correspondait pas à sa somme de contrôle et a été écarté). Pour Claude Code, cliquez sur Installer Claude Code sur sa carte ; si vous l’avez installé vous-même, ouvrez un terminal, vérifiez que claude --version fonctionne, puis Réglages › Fournisseurs d’IA › Rechercher à nouveau.

Erreurs git. L’application explique les plus courantes en une phrase — identifiants, un dépôt distant qui a avancé, un fichier de verrouillage, un arbre de travail modifié, des conflits — et garde la sortie complète dans le terminal du worktree.

Aucune mise à jour n’apparaît. Vérifiez Réglages › Notifications › Proposer les mises à jour, puis Rechercher des mises à jour ; l’application doit pouvoir joindre github.com.

Pour tout le reste : ouvrez une issue en décrivant ce que vous avez fait, ce que vous attendiez et ce qui s’est passé.

Confidentialité et sécurité

Tout s’exécute sur votre ordinateur. L’application elle-même se connecte à internet pour une seule chose : consulter les versions de ce site à la recherche de mises à jour. Les agents parlent à leurs fournisseurs avec vos comptes ; git parle à vos dépôts distants avec vos identifiants. Les jetons de fournisseur que l’application conserve sont stockés dans le trousseau du système d’exploitation. L’interface s’exécute dans un bac à sable, chaque requête qui nomme un chemin est vérifiée par rapport aux dépôts que vous avez réellement ouverts, et aucune commande n’est jamais construite à partir d’une chaîne shell.

Pour vérifier qu’un téléchargement est bien le nôtre, voir Mon téléchargement est-il authentique ? sur la page de téléchargement.
